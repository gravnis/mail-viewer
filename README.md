# Mail Viewer — просмотр почты через расширение Chrome + админка

Расширение показывает входящие письма по IMAP. **Только чтение** — отправить, ответить
или удалить письмо нельзя (такого кода нет ни в расширении, ни на сервере).

## Модель

```
          ┌────────────── админка (на сервере) ──────────────┐
          │ админ загружает список почт (адрес+пароль),       │
          │ пул прокси и ключи доступа                        │
          └───────────────────────┬──────────────────────────┘
                                   │  админ в ЛС выдаёт сотруднику
                                   │  адрес+пароль нужных ящиков и ключ
                                   ▼
расширение Chrome ──HTTPS+ключ──▶ сервер ──через прокси──▶ IMAP почты
 (сотрудник вводит                 проверяет, что адрес
  адрес+пароль,                    есть в списке админа,
  видит только их)                 логинится паролем сотрудника
```

- **Админ** в админке загружает аккаунты (строками), прокси и ключи доступа. Добавлять
  может только админ. В списке админ видит адреса и тип (Outlook/обычная); сами строки и
  токены в интерфейсе не показываются.
- **Сотрудник** получает в ЛС строку аккаунта (целиком) и ключ доступа. В расширении он
  **вставляет строку целиком** и видит **только** эти ящики. Чужих не видит.
- **Сервер** пускает к почте, только если **точно такая строка** есть в базе админа
  (сверяет по хешу), и ходит в IMAP **только через прокси**. Доступ = ключ + точная строка.

### Формат аккаунтов

- **Outlook / Hotmail** (вход по OAuth, т.к. Microsoft отключил пароль для IMAP) —
  поля через `----`:
  `email----password----client_id----refresh_token----резервная_почта----…`
  `client_id` (UUID) и `refresh_token` (`M.C5…`) определяются по виду, порядок неважен,
  лишние поля игнорируются (но должны совпадать со строкой, выданной сотруднику).
- **Обычная почта** — `email:password` (пароль — всё после первого разделителя).

Два IP скрыты: выходной — прокси (ротация на коннекте; без прокси сервер к почте не
идёт); входной — Cloudflare Tunnel (сервер слушает только localhost, портов наружу нет).

## 1. Сервер

Node.js **22.5+** (используется встроенный `node:sqlite`) или Docker.

```bash
cd server
cp .env.example .env
```

В `.env` обязательно:
- `ADMIN_PASSWORD` — пароль входа в админку (минимум 16 символов рекомендуется).
- `SECRET_KEY` — ключ шифрования (`openssl rand -hex 32`). Если пусто, создастся в
  `data/secret.key` — **не теряйте** этот файл, иначе не расшифровать сохранённые данные.
- `TRUST_PROXY_HEADERS=true` — только если сервер стоит за Cloudflare/nginx (иначе оставьте false).

Запуск:
```bash
npm install --omit=dev
npm start                     # http://127.0.0.1:8787
```
Или Docker: `docker compose up -d --build`. Данные (БД + ключ) — в `server/data/`
(или томе `mailviewer-data`), бэкапьте их.

## 2. Скрыть входной IP (Cloudflare Tunnel)

1. В Cloudflare Zero Trust создай туннель, получи токен.
2. Публичный хостнейм (`mail.твойдомен.com`) → `http://mail-viewer:8787` (Docker) или `http://127.0.0.1:8787`.
3. ```bash
   echo "CLOUDFLARE_TUNNEL_TOKEN=токен" >> server/.env
   docker compose --profile tunnel up -d
   ```
HTTPS обязателен (расширение принимает только `https://`). Для теста по http поставь `COOKIE_INSECURE=true`.

## 3. Админка

Открой адрес сервера → введи `ADMIN_PASSWORD`. Разделы:
- **Почты** — «+ Добавить почты»: вставь аккаунты, по строке на аккаунт (форматы выше).
  Можно сразу много строк.
- **Прокси** — добавить/импортировать пул (socks5 рекомендуется).
- **Ключи доступа** — создать ключ для сотрудника (показывается один раз). Ключ нужен,
  чтобы вообще пользоваться расширением.

Выдавай сотруднику: ключ доступа + строки аккаунтов, которые он должен вести.

## 4. Расширение (сотруднику)

1. Chrome → `chrome://extensions` → **Режим разработчика** → **Загрузить распакованное** → папка `extension/`.
2. ⚙ Настройки: адрес сервера + ключ доступа (выданы админом). Chrome спросит разрешение на адрес — разрешить.
3. ＋ добавить ящик: **вставь строку аккаунта целиком**, как выдал админ.
4. Вкладки **Новые** / **Все**, клик по письму — просмотр.

Строки хранятся только в браузере сотрудника. Сервер их не сохраняет — сверяет по хешу,
что такая строка есть в базе, и подключается.

## 5. Про запрет отправки

Отправки нет нигде в коде — сервер умеет только список папок, список писем, одно письмо.

## Безопасность

Проведён аудит, критичные пункты закрыты:
- Вход в админку: отдельный строгий лимит попыток (защита от перебора), сравнение пароля
  постоянной длины, сессия в cookie `__Host-` (HttpOnly, Secure, SameSite=Strict),
  привязана к паролю (смена `ADMIN_PASSWORD` рвёт все сессии).
- IP для лимитов берётся из заголовков только при `TRUST_PROXY_HEADERS=true`.
- Любой некорректный запрос обрабатывается (нет падения процесса); глобальные обработчики ошибок.
- Пароли/токены/прокси шифруются в БД (AES-256-GCM с привязкой к записи — нельзя подменить блоб).
- Доступ к API — по ключу; к ящику — только если адрес в списке + верный пароль.
- Исходящие — только через прокси; без прокси подключение не выполняется.
- IMAP только по порту 993 (TLS), открывается `readOnly` (письма не меняются).
- HTML письма — в sandbox-iframe с CSP без скриптов, ссылки некликабельны, внешние ресурсы не грузятся.
- Админка отдаётся с CSP/anti-framing; тексты ошибок не содержат адресов.
- Лимит одновременных IMAP-соединений; базовый журнал входов/действий.

Остаются как доработки на будущее (не блокеры): серверный список активных сессий для
мгновенного отзыва, ротация ключа шифрования, вынос `secret.key` в отдельное хранилище.
